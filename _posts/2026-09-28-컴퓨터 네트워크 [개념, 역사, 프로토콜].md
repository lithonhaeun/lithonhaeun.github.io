# 네트워크 개념
## 1. 네트워크란? (정의)
"네트워크"라는 단어는 관점에 따라 다르게 정의됩니다.

- 수학적 관점 (Newman): 점(node)들이 선(edge)으로 쌍을 이루어 연결된 집합
- 컴퓨터공학적 관점 (Tanenbaum): 하나의 기술로 상호 연결된 **자율**적인 컴퓨터들의 집합
- 시스템적 관점 (Peterson & Davie): 전통적 통신망은 음성이나 영상처럼 한 
종류의 데이터만 다루고 특수 장치에 연결되지만, 컴퓨터 네트워크는 범용적

이 정의들을 종합하면 네트워크의 일반적 정의는 2개 이상의 개체(Entity) 사이에서 
무언가(commodity)를 운반하는 체계입니다. 
교통망, 전력망, 우편망, 상수도, 전화망, 지하철 노선도도 네트워크라 할 수 있겠죠?

### 컴퓨터 네트워크의 핵심은 '정보'와 '통신 채널'

컴퓨터 네트워크는 범용 컴퓨터(general-purpose Computers)들이 
통신 채널(communication channels)로 연결되어 정보가 이동하는 집합체입니다.
<br>
일반 네트워크가 물건이나 에너지를 나른다면, 컴퓨터 네트워크는 정보를 나릅니다. 
종종 네트워크들의 불특정 집합, 요즘은 서버까지 포함해 클라우드라고 부르는데, 
이 용어는 1996년 컴팩(Compaq)의 보고서에서 인터넷을 구름 모양으로 그린 데서
비롯되었습니다.

### 교통망과 네트워크를 빗대어 봅시다!

| 교통망 | 컴퓨터 네트워크         |
|---|------------------|
| 차량 / 사람 | packet / payload |
| 도로 주소 | IP 주소            |
| 교차로 | 브릿지 / 라우터        |
| 도로, 고속도로 | 링크 / 경로          |
| 교통 정체 | 네트워크 혼잡          |
| 신호등 | 흐름 제어            |
| 우회 경로 | 대체 경로            |
| 카풀 전용차선(HOV) | 스트림 우선순위         |
| 목적지까지 길 찾기 | 라우팅 알고리즘         |

저는 여기서 라우터와 IP 주소가 헷갈렸는데요. 라우터는 이름 그대로
route(경로)를 다루는 장치입니다. 라우터들은 서로 정보를 주고받으며
라우팅 알고리즘으로 경로를 계산하고, 그 결과를 포워딩 테이블에
미리 정리해 둡니다. 그리고 패킷이 들어오면 목적지 IP 주소를 보고
포워딩 테이블을 찾아 다음 라우터로 forward(전달)합니다.



## 2. 네트워크를 이루는 요소

네트워크는 **노드**와 **링크** 두 가지로 구성됩니다.

![노드](/assets/img/img_3.png)

노드(Node): 특수 목적 장치 (네트워크에서 동작하는 하드웨어들)

- PC와 서버
- 스위치와 브릿지
- 라우터

![링크](/assets/img/img_4.png)

링크(Link): 노드 사이의 연결

- 광섬유 케이블
- 동축 케이블
- 무선 채널

## 3. 인터넷은 '네트워크의 네트워크' 이게 뭔말일까?
하나의 네트워크에서 다른 네트워크로 전송하고자 할때 각자의 기술이 달라 서로 연결이 되지 않는 문제가 있었습니다.
그래서 네트워크의 네트워크를 만들어 상호 연결하는 **인터넷**이 등장했습니다<br><br>
인터넷은 여러 ISP(인터넷 서비스 제공자)가 서로 연결된 network of networks입니다. 
참고로 대문자 'I'nternet은 전 세계 공용 인터넷을, 소문자 'i'nternet은 일반적인 상호연결망을
뜻하며, 조직 내부의 사설망은 intranet(인트라넷)이라 부릅니다.


![img_5.png](/assets/img/img_5.png)

1. Communication Links[
   1. 광섬유, 구리선, 무선, 위성 등]()
   2. 전송 속도 (transmission rate / data rate) : bandwith (대역폭)
      1. 1 Giga bits per second(bps) = 10의 9승 비트를 1초에 밀어넣음
3. Packet switches: 패킷(데이터 조각)을 전달하는 장비 (라우터, 스위치)
4. Networks: 장치, 라우터, 링크의 집합으로, 하나의 조직이 관리

  - Hosts : 스마트폰, 노트북, 서버, 클라이언트 같은 끝단 장치 (데이터센터도 가능함)

  - 네트워크에 접속할 수 있게 하는것
  - Network edge에 이어, 유무선 통신 링크(access network)
    - Ex. 와이파이

    - 기술의 종류 다양x and 비쌈 

### 서비스(봉사, 용역-돈을 주고 남에게 일을 맡기는 것) 관점에서의 인터넷:
- 두 가지 통신 서비스 제공:  
  - 신뢰성 있는 데이터 전달(reliable) ➡️ 가급적 reliable 하도록 위에서 추가적인 작업함 

  - ② 최선형(best-effort) 비신뢰성 전달 ➡️ 책임을 지지 않는다. 
  <br> 즉, 전달 과정에서 여력이 있으면 전달하고 여력이 없으면 포기한다.
<br>ex. 등기우편 - 배달 과정에서 기록은 제공하지만 보상은 하지 않음
- 통신 인프라가 구축된다면 분산적으로 동작하는 애플리케이션(웹, VoIP, 이메일, 게임, 전자상거래, 파일공유)을 가능케 함
- 프로그래밍 인터페이스 제공: 앱이 인터넷 전송 서비스에 "연결(connect)"하는 훅(hook) 제공, 
우편 서비스처럼 다양한 서비스 옵션 제공 <br>(TCP- 신뢰적 / UDP- unreliable)


### 왜 지금의 계층 구조가 되었을까?
![](/assets/img/20261002-capture-4.png)

수백만 개의 access ISP(internet service provider)를 어떻게 연결할지 단계별로 생각해 보면 이유가 보입니다.

1. 전부 직접 연결: 연결이 O(N²)개 필요해서 확장이 불가능합니다.
2. 글로벌 ISP 하나에 연결: 경제적으로는 그럴듯하지만, 돈이 되는 사업이면 경쟁자가 생깁니다.
3. ISP가 여러 개로 분화: 서로 연결되고 싶어 하니 IXP(인터넷 교환 지점)에서 만나 피어링합니다.
4. 지역 ISP 등장: access 망과 ISP 사이를 이어 줍니다.
5. 콘텐츠 제공자망 등장: Google, Microsoft, Akamai 같은 기업이 자체 망으로 사용자 가까이 서비스를 제공합니다.

## 4. 인터넷 역사 한눈에 보기

### 📌 패킷 교환 초기 (1961~1972)
- 1961: Kleinrock이 큐잉 이론으로 패킷 교환의 효율성을 보였습니다.
- 1964: Baran이 군사망에 적용할 패킷 교환을 제안했습니다.
- 1967: ARPA가 ARPAnet을 구상했습니다.
- 1969: 첫 ARPAnet 노드가 가동되었습니다.
- 1972: 공개 시연, 첫 호스트 간 프로토콜 NCP, 첫 이메일 프로그램이 나왔고 노드는 15개가 되었습니다.

### 📌 인터네트워킹 시대 (1972~1980)
- 1970: 하와이의 ALOHAnet 위성망
- 1974: Cerf와 Kahn이 네트워크 연결 아키텍처를 제안했습니다. 핵심 원칙은 최소주의와 자율성, 최선형 서비스, 상태 비저장 라우팅, 탈중앙화 제어이고, 오늘날 인터넷의 뼈대가 됐습니다.
- 1976: Xerox PARC에서 이더넷이 개발되었습니다.
- 1970년대 후반: DECnet, SNA 같은 기업별 독자 네트워크가 난립했습니다.

### 📌 프로토콜 확산 (1980~1990)
- 1982: SMTP 이메일 프로토콜 정의
- 1983: TCP/IP 배포, DNS 정의
- 1985: FTP 정의
- 1988: TCP 혼잡 제어 도입

이 시기에 CSnet, NSFnet 등 국가망이 생겼고 약 10만 대의 호스트가 연결되었습니다.

### 📌 상업화와 웹의 시대 (1990~2000년대)
ARPAnet이 퇴역하고 Berners-Lee가 웹(HTML, HTTP)을 만들었습니다. 1994년 NCSA Mosaic 브라우저가 나오고 웹이 상업화되었으며, 2000년 닷컴 버블이 터졌습니다. 메신저와 P2P 같은 킬러앱이 등장하고 네트워크 보안도 중요한 이슈로 떠올랐습니다.

### 📌 현대 인터넷 (2005~현재)
- 10~수백 Mbps급 초고속 브로드밴드 보급
- 2008년 SDN(소프트웨어 정의 네트워크) 등장
- 4G/5G와 WiFi로 무선 접속이 보편화
- Google, Facebook, Microsoft가 자체 네트워크 구축
- AWS, Azure 같은 클라우드 확산
- 2017년에는 모바일 기기가 유선 기기를 추월했고, 2023년 기준 약 150억 개 기기가 인터넷에 연결되어 있습니다.

## 5. 프로토콜: 컴퓨터들의 대화 규칙

### 프로토콜이란?

protocol의 원래 뜻은 외교 행사를 다스리는 공식 절차입니다. 이 정의 때문에 ARPANET 엔지니어들이 NCP를 Network Control Program에서 Network Control Protocol로 바꿔 부르기 시작했다는 일화가 있습니다.

사람의 대화와 비교하면 이해가 쉽습니다.

- 사람: "안녕" → "안녕" → "몇 시야?" → "2시야"
- 컴퓨터: TCP 연결 요청 → TCP 연결 응답 → GET 요청 → 파일 전송

프로토콜이 필요한 이유는 서로 상대방의 상태를 완전히 알지 못하는 분산된 개체들이 시간에 걸쳐 메시지를 주고받기 때문입니다.

### 프로토콜의 3요소

| 요소 | 의미                         |
|---|----------------------------|
| 구문 (Syntax) | 메시지의 구조와 형식 (헤더 필드, 문자열 등) |
| 의미 (Semantics) | 어떤 요청과 동작, 응답이 있는지         |
| 타이밍 (Timing) | 이벤트의 순서와 시점 (언제 통신할 것인가)   |

### 프로토콜의 핵심 특성
>1. 프로토콜을 이야기 할때는 항상 분산된 엔티티 (서로 상대방의 상태를 완전히 알지 못하는)가 
전제된다. ➡️ 각각의 엔티티는 불완전하다
>2. 프로토콜에 의해 규정된 메시지 교환은 데이터 통신이나 상태 동기화를 위해 
시간에 걸쳐 발생한다.

## 6. 표준과 인터넷 표준화

### 표준이 왜 필요할까?

표준은 무언가를 하는 방법에 대해 널리 합의된 방식입니다. 표준이 없으면 기술은 서로 호환되지 않아 작동하지 않습니다.

- 표준 개발 기구(SDO): ISO, IEC, ANSI, ITU-T, ETSI, IEEE, IETF, W3C 등. 이 중 IETF, W3C, IEEE는 꼭 기억해야 합니다.
- 사실상 표준(de facto): 시장에서 널리 쓰여 굳어진 표준
- 공식 표준(de jure): 공식 절차로 제정된 표준
- 예시로 PDF는 1993년 사실상 표준이 되었고, 2005년 PDF/A가 ISO 19005-1로 공식 표준이 되었습니다.

### 통신 규제 기관
통신 기술은 정부 규제를 받습니다. 한국은 방송통신위원회(KCC), 미국은 FCC, 유럽은 EC, ETSI, ECC가 관련 역할을 합니다. 전자제품에 붙은 KC, FCC, CE 마크가 바로 이런 규제와 관련된 인증입니다.

### 인터넷 표준은 어떻게 만들어질까?

인터넷 표준은 IETF가 만들고 발행합니다.

1. Internet-Draft: IETF에 제출된 명세 초안
2. RFC(Request for Comments): 승인되면 편집과 번호 부여를 거쳐 공개 문서로 발행
3. Proposed Standard: 안정적이고 여러 그룹에서 구현된 명세
4. Internet Standard: 충분히 검증되어 널리 준수되는 명세

과거에 있던 Draft Standard 단계는 현재 폐지되었습니다(RFC 6410). 표준 목록은 RFC Editor 사이트(rfc-editor.org/standards)에서 볼 수 있습니다.
