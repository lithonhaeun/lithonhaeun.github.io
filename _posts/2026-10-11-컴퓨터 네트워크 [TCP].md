# TCP 들어가기

전편에서 이더넷, 와이파이, 스위치, 라우터처럼 데이터가 실제로 지나가는 기술들을 살펴봤다면,
여기서는 계층을 하나 올라가 전송 계층, 그중에서도 TCP를 다룹니다.

---

> ### 목차
>
> 1. 전송 계층 기초 (Transport Layer Basics)
>    - 전송 계층이 하는 일, TCP와 UDP의 차이, 포트 번호를 이용한 다중화와 역다중화(비연결형 / 연결형)를 정리합니다.
> 2. TCP 서비스 (TCP Services)
>    - TCP가 응용 계층에 제공하는 세 가지 서비스인 연결 지향, 신뢰성, 바이트 스트림을 살펴봅니다.
> 3. TCP 특징 (TCP Features)
>    - 순서 번호, 누적 ACK, 피기배킹, 재전송 타이머, 전이중 통신처럼 TCP가 신뢰성을 만들어 내는 방법을 알아봅니다.
> 4. TCP 헤더와 캡슐화 (TCP Header and Encapsulation)
>    - 포트 번호, 순서 번호, 확인 응답 번호, 플래그, 윈도 크기, 체크섬 등 TCP 헤더의 각 필드가 하는 일을 하나씩 봅니다.

## 1. 전송 계층 기초 (Transport Layer Basics)
### 전송 서비스와 프로토콜 (Transport Services and Protocols)

> 핵심
> 
> 전송 계층은 서로 다른 호스트에서 실행 중인 응용 프로세스들 사이에 논리적 통신을 제공한다.

- 전송 서비스와 프로토콜
  - 서로 다른 호스트에서 실행 중인 응용 프로세스 사이에 논리적 통신(logical communication)을 제공한다.
  - 전송 프로토콜은 종단 시스템(end system)에서 동작한다.
    - 송신자: 응용 메시지를 세그먼트(segment)로 나누어 네트워크 계층에 넘긴다.
    - 수신자: 세그먼트를 다시 메시지로 조립해 응용 계층에 넘긴다.
  - 인터넷 응용 프로그램이 쓸 수 있는 전송 프로토콜은 두 가지이다.
    - TCP, UDP

논리적 통신이란, 실제로는 데이터가 여러 라우터와 링크를 거쳐 가지만
응용 프로세스 입장에서는 상대 프로세스와 직접 연결된 것처럼 보인다는 뜻이다.

전송 계층에서 다루는 데이터 단위는 세그먼트이다.

### 송신자 쪽 전송 계층의 동작 (Transport Layer Actions: Sender)

> 핵심
> 
> 송신 측 전송 계층은 응용 메시지에 헤더를 붙여 세그먼트를 만들고, 이를 IP(네트워크 계층)에 넘긴다.

- 전송 계층의 동작
- 송신자는
  1. 응용 계층으로부터 메시지를 넘겨받는다.
  2. 세그먼트 헤더 필드의 값들을 정한다.
  3. 세그먼트를 만든다.
  4. 세그먼트를 IP에 넘긴다.

헤더 필드에 들어가는 대표적인 값이 출발지 포트 번호와 목적지 포트 번호이다.

|헤더	|PDU| 	적히는 것	                |무엇을 가리키나|
|---|---|------------------------|---|
|네트워크 계층 (IP) 헤더|	N-PDU (데이터그램)| 	출발지 IP 주소, 목적지 IP 주소  |	어느 컴퓨터|
|전송 계층 (TCP/UDP) 헤더|T-PDU (세그먼트)| 	출발지 포트 번호, 목적지 포트 번호	 | 그 컴퓨터 안의 어느 프로그램      |

### 수신자 쪽 전송 계층의 동작 (Transport Layer Actions: Receiver)

> 핵심
> 
> 수신 측 전송 계층은 IP로부터 받은 세그먼트의 헤더를 확인하고, 응용 메시지를 꺼내 소켓을 통해 알맞은 응용 프로그램에 올려 보낸다.

- 수신자는
  1. IP로부터 세그먼트를 받는다.
  2. 헤더 값들을 확인한다.
  3. 응용 계층 메시지를 꺼낸다.
  4. 소켓(socket)을 통해 메시지를 응용 프로그램으로 역다중화(demultiplex)해 올려 보낸다.

송신자가 헤더 값을 "정했다면", 수신자는 그 헤더 값을 "보고" 메시지를 어디로 보낼지 결정한다.
이때 여러 프로그램 중 알맞은 하나를 골라 넘겨주는 것을 역다중화라고 한다.

소켓은 응용 프로그램과 전송 계층 사이의 출입구이다.

### 인터넷의 두 전송 프로토콜 (Two Principal Internet Transport Protocols)

> 핵심
> 
> TCP는 신뢰성 있고 순서가 보장되는 전달을, UDP는 신뢰성도 순서도 보장하지 않는 단순한 전달을 제공한다. 둘 다 지연과 대역폭은 보장하지 않는다.

- 인터넷의 두 가지 주요 전송 프로토콜
  - TCP: 전송 제어 프로토콜 (Transmission Control Protocol)
    - 신뢰성 있고, 순서대로 전달 (reliable, in-order delivery)
      - 패킷 손실시 재전송
      - 최종 전송 실패시 알려줌
    - 혼잡 제어 (congestion control)(보내는 양)
    - 흐름 제어 (flow control)(데이터량)
    - 연결 설정 (connection setup)
  - UDP: 사용자 데이터그램 프로토콜 (User Datagram Protocol)
    - 신뢰성 없고, 순서 없는 전달 (unreliable, unordered delivery)
    - "최선형(best-effort)" IP에 군더더기 없이 기능만 조금 더한 것 (no-frills extension)
  - 제공되지 않는 서비스
    - 지연 보장 (delay guarantees)
    - 대역폭 보장 (bandwidth guarantees)

| 구분 | TCP | UDP |
|---|---|---|
| 신뢰성 | 있음 (잃어버리면 다시 보냄) | 없음 |
| 순서 | 보장 | 보장 안 함 |
| 연결 설정 | 있음 | 없음 |
| 흐름 제어 | 있음 | 없음 |
| 혼잡 제어 | 있음 | 없음 |
| 지연, 대역폭 보장 | 없음 | 없음 |

UDP는 IP가 하는 최선형 전달에 포트 번호(프로세스 구분)와 체크섬 정도만 더한 프로토콜이다.
TCP는 그 위에 신뢰성, 순서 보장, 연결 관리, 흐름 제어, 혼잡 제어까지 직접 해 준다.

두 프로토콜 모두 "얼마 안에 도착한다"거나 "초당 얼마 이상 보낸다"는 약속은 하지 못한다.

### TCP/IP 프로토콜 스위트 속의 TCP

![](/assets/img/20261012-capture.png)

TCP/IP 프로토콜 스위트는 계층마다 여러 프로토콜이 모여 있는 묶음이다.

이 중 TCP는 전송 계층에 있으며, HTTP, SMTP, FTP처럼 데이터를 빠짐없이 받아야 하는 응용 프로토콜들이 TCP 위에서 동작한다.
"TCP/IP"라는 이름 자체가 전송 계층의 TCP와 네트워크 계층의 IP에서 따온 것이다.

### 다중화와 역다중화 (Multiplexing and Demultiplexing)

> 핵심
> 
> 호스트의 전송 계층은 보낼 때 다중화를, 받을 때 역다중화를 수행한다.

- 호스트의 전송 계층은 다중화와 역다중화를 수행한다.
- 송신자의 다중화 (multiplexing as sender)
  - 여러 소켓에서 온 데이터를 처리하고, 전송 헤더를 붙인다. (이 헤더는 나중에 역다중화에 쓰인다.)
- 수신자의 역다중화 (demultiplexing as receiver)
  - 헤더 정보를 이용해, 받은 세그먼트를 올바른 소켓에 전달한다.

그림에는 세 대의 호스트가 있고, 그중 한 호스트에서는 프로세스 P1, P2가 동시에 네트워크를 쓰고 있다.

| 역할 | 하는 일 | 쓰는 정보 |
|---|---|---|
| 다중화 (송신) | 여러 소켓의 데이터를 모아 헤더를 붙이고 하나의 네트워크 계층으로 내려보냄 | 헤더에 포트 번호를 적음 |
| 역다중화 (수신) | 도착한 세그먼트를 알맞은 소켓으로 나눠 줌 | 헤더의 포트 번호를 읽음 |

송신자가 헤더에 적은 값이, 수신자가 역다중화할 때 보는 값이 된다.
그래서 다중화와 역다중화는 항상 짝으로 동작한다.

### 어느 프로세스로 보낼까? (Which Process?)

질문: 전송 계층은 메시지를 Netflix 프로세스나 Skype 프로세스가 아니라 Firefox 브라우저 프로세스에 전달해야 한다는 것을 어떻게 알았을까?

### 전송 계층의 다중화 (Multiplexing in Transport Layer)

> 핵심
> 
> 호스트는 IP 주소와 포트 번호를 함께 사용해, 도착한 세그먼트를 알맞은 소켓으로 보낸다.

- 호스트는 IP 데이터그램을 받는다.
  - 각 데이터그램에는 출발지 IP 주소와 목적지 IP 주소가 있다.
  - 각 데이터그램은 전송 계층 세그먼트를 하나씩 싣고 있다.
  - 각 세그먼트에는 출발지 포트 번호와 목적지 포트 번호가 있다.
- 호스트는 IP 주소와 포트 번호를 이용해 세그먼트를 알맞은 소켓으로 보낸다.

TCP/UDP 세그먼트 형식 (32비트 너비)<br>
데이터그램 하나 안에 세그먼트 하나가 들어 있는 구조이다.

| 정보 | 들어 있는 곳 |
|---|---|
| 출발지 / 목적지 IP 주소 | IP 데이터그램 헤더 (네트워크 계층) |
| 출발지 / 목적지 포트 번호 | TCP/UDP 세그먼트 헤더 (전송 계층) |

세그먼트 헤더의 맨 앞에는 TCP든 UDP든 출발지 포트 번호와 목적지 포트 번호가 온다.
포트 번호는 각각 16비트라서, 두 개를 합쳐 첫 줄(32비트)을 채운다.

소켓을 찾을 때는 두 헤더에 나뉘어 있는 IP 주소와 포트 번호를 함께 본다.

### 비연결형 역다중화 (Connectionless Demultiplexing)

> 핵심
> 
> UDP는 목적지 포트 번호만 보고 소켓을 찾는다. 그래서 출발지가 달라도 목적지 포트 번호가 같으면 모두 같은 소켓으로 들어간다.

- 비연결형 역다중화 (UDP가 사용)
  - 다중화 규칙: UDP 소켓으로 보낼 데이터그램을 만들 때, 반드시 다음을 지정해야 한다.
    - 목적지 IP 주소
    - 목적지 포트 번호
  - 역다중화 규칙: 수신 호스트가 UDP 세그먼트를 받으면
    - 세그먼트의 목적지 포트 번호를 확인한다.
    - 그 포트 번호를 가진 소켓으로 UDP 세그먼트를 보낸다.
- 목적지 포트 번호가 같은 IP/UDP 데이터그램은, 출발지 IP 주소나 출발지 포트 번호가 달라도 수신 호스트에서 같은 소켓으로 전달된다.

| 구분 | 보내는 쪽이 지정하는 것 | 받는 쪽이 보는 것 |
|---|---|---|
| UDP | 목적지 IP 주소, 목적지 포트 번호 | 목적지 포트 번호 |

데이터그램이 이미 이 호스트에 도착했다면 목적지 IP 주소는 당연히 자기 자신이므로,
UDP 소켓을 고를 때 실제로 구분에 쓰이는 값은 목적지 포트 번호 하나이다.

그 결과, 여러 클라이언트가 같은 포트로 보낸 데이터가 모두 하나의 소켓으로 모인다.
누가 보냈는지는 소켓이 아니라 응용 프로그램이 데이터그램의 출발지 정보를 보고 구분해야 한다.

즉 : source port 는 적절한 소켓에 세그먼트의 데이터를 전달하는 과정에서 관여하지 않는다

### 연결형 역다중화 (Connection-oriented Demultiplexing)

> 핵심
> 
> TCP 연결은 출발지 IP, 출발지 포트, 목적지 IP, 목적지 포트의 4-튜플로 구분되며, 수신자는 이 네 값을 모두 사용해 세그먼트를 알맞은 소켓으로 보낸다

- 연결형 역다중화
  - RFC 793에 따르면, 소켓, 순서 번호, 윈도 크기 등 각 데이터 스트림(tcp에서 데이터 흐름)의 상태 정보를 묶은 것을 연결(connection)이라고 한다.
  - 소켓 한 쌍(로컬 소켓과 원격 소켓)이 각 TCP 연결을 유일하게 구분한다.
    - 출발지 IP 주소
    - 출발지 포트 번호
    - 목적지 IP 주소
    - 목적지 포트 번호
  - 다중화 규칙: 송신자가 TCP 세그먼트를 담은 IP 데이터그램을 만들 때, TCP/IP 헤더에 위의 4-튜플이 나뉘어 들어간다.
  - 역다중화 규칙: 수신자는 네 값(4-튜플)을 모두 사용해 TCP 세그먼트를 알맞은 소켓으로 보낸다.
  - 이 규칙 덕분에 서버는 동시에 많은 TCP 소켓을 운영할 수 있다.
    - 각 소켓은 자기만의 4-튜플로 구분된다.
    - 각 소켓은 서로 다른 접속 클라이언트와 연결된다.

4-튜플은 두 헤더에 나뉘어 들어 있다.

| 값 | 들어 있는 헤더 |
|---|---|
| 출발지 IP 주소, 목적지 IP 주소 | IP 헤더 (네트워크 계층) |
| 출발지 포트 번호, 목적지 포트 번호 | TCP 헤더 (전송 계층) |

UDP와 TCP의 역다중화를 비교하면 다음과 같다.

| 구분 | 소켓을 고를 때 보는 값 | 결과 |
|---|---|---|
| UDP (비연결형) | 목적지 포트 번호 | 출발지가 달라도 같은 소켓 |
| TCP (연결형) | 출발지 IP, 출발지 포트, 목적지 IP, 목적지 포트 | 출발지가 다르면 다른 소켓 |

연결이란 단순히 주소 쌍만이 아니라, 그 사이에서 주고받는 데이터의 상태(순서 번호, 윈도 크기 등)까지 포함한 개념이다.
### 연결형 역다중화 예제 (Connection-oriented Demultiplexing: Example)

> 핵심
> 
> 목적지 IP 주소(B)와 목적지 포트(80)가 모두 같은 세그먼트 세 개가, 4-튜플이 달라서 서버의 서로 다른 소켓으로 역다중화된다.

- 세 세그먼트 모두 목적지 IP 주소 B, 목적지 포트 80으로 향하지만, 서로 다른 소켓으로 역다중화된다.

## 2. TCP 서비스 (TCP Services)

전송 계층의 기본 역할을 봤으니, 이제 TCP가 응용 계층에 무엇을 제공하는지 살펴본다.
TCP의 서비스는 연결 지향, 신뢰성, 바이트 스트림 세 가지로 요약된다.

### TCP가 제공하는 서비스 (TCP Services)

> 핵심
> 
> TCP는 <mark class="pink">connection-oriented </mark>(연결 지향적)이고, 
> <mark class="pink">reliable </mark>(신뢰성 있는), 
> <mark class="pink">byte stream service </mark>(바이트 스트림 서비스)를 제공한다.

- TCP는 연결 지향(connection-oriented), 신뢰성(reliable), 바이트 스트림(byte stream) 서비스를 제공한다.
  - TCP와 UDP는 같은 네트워크 계층(IP)을 사용하지만,
  - TCP는 응용 계층에 UDP와 완전히 다른 서비스를 제공한다.

| 서비스 | 의미 | UDP와 비교 |
|---|---|---|
| 연결 지향 | 데이터를 주고받기 전에 서로 연결을 맺는다 | UDP는 연결 없이 바로 보낸다 |
| 신뢰성 | 데이터가 빠짐없이, 순서대로, 깨지지 않고 도착하게 한다 | UDP는 도착을 보장하지 않는다 |
| 바이트 스트림 | 데이터를 메시지 단위가 아니라 끊김 없는 바이트의 흐름으로 다룬다 | UDP는 메시지(데이터그램) 단위로 보낸다 |

TCP와 UDP 아래의 IP는 똑같이 비연결, 최선형 전달을 한다.
같은 IP 위에서 UDP는 거의 그대로 전달하고, TCP는 위의 세 가지 서비스를 직접 만들어 낸다.

### 연결 지향의 의미 (Connection-oriented)

> 핵심
> 
> TCP를 쓰는 두 응용 프로그램은 데이터를 주고받기 전에 반드시 연결을 맺어야 하며, 하나의 TCP 연결에는 정확히 두 개의 끝점만 있다.

- 연결 지향이란
  - TCP를 사용하는 두 응용 프로그램은 데이터를 주고받기 전에, 서로 연락해 연결을 맺어야 한다.
  - 하나의 TCP 연결에서 통신하는 끝점(endpoint)은 정확히 두 개이다.
    - 연결은 두 끝점 사이에 동기화된 상태(synchronized states)로 여겨진다.
      - tcp는 상태를 저장한다.
### 바이트 스트림 서비스 (Byte Stream)

> 핵심
> 
> TCP는 응용 프로그램에 바이트 스트림이라는 추상화를 제공한다. TCP는 바이트의 내용을 해석하지 않고, 메시지 경계도 표시하지 않는다.

- TCP는 응용 프로그램에 바이트 스트림 추상화(abstraction)를 제공한다.
  - TCP는 바이트 스트림 안의 바이트 내용을 전혀 해석하지 않는다.
  - TCP는 레코드 표시(record marker)나 메시지 경계(message boundary)를 자동으로 넣지 않는다.
    - 레코드 표시란 응용 프로그램이 한 번에 쓴(write) 범위를 나타내는 표시이다.
    - 각 끝점은 읽고 쓰는 크기를 각자 따로 정한다.
  - 전이중(full duplex) 서비스: 8비트 바이트의 흐름이 연결의 양방향으로 오가며, 각 방향은 반대 방향과 독립적이다.
    - duplex : 양방향 데이터 교환
      - half : ~오바 처럼 끝났다는거 알려줌 (동시 전송 x)
      - full : 상대 상태 상관 없이 동시에 보내는거 가능
    - simplex : 한방향 데이터 교환

TCP는 응용 프로그램이 몇 번에 나눠 썼는지를 기억하지 않는다.
예를 들어 송신 측이 데이터를 10바이트, 20바이트, 50바이트로 세 번 써도,

전이중이란 A → B 방향과 B → A 방향의 바이트 흐름이 동시에, 서로 독립적으로 오갈 수 있다는 뜻이다.
