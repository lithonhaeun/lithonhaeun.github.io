showfile1_nobuf 파일에는 이런 코드가 있어요
```
/* Copy from file to stdout one character at a time */
#include "csapp.h"

int main(int argc, char *argv[]) 
{
    char c;
    int infd = STDIN_FILENO;
    if (argc == 2) {
	infd = Open(argv[1], O_RDONLY, 0);
    }
    while(Read(infd, &c, 1) != 0)
	Write(STDOUT_FILENO, &c, 1);
    exit(0);
}
```

코드 한 줄씩 보기

| 코드 | 의미 |
|---|---| 
| `char c;` | 읽은 글자 1바이트를 담아 둘 변수. 이 프로그램의 버퍼는 1바이트짜리이다 |
| `int infd = STDIN_FILENO;` | 읽을 대상의 기본값을 표준 입력(0번, 키보드)으로 정한다 |
| `if (argc == 2)` | 실행할 때 파일 이름을 하나 줬는지 확인한다|
| `infd = Open(argv[1], O_RDONLY, 0);` | 그 파일을 읽기 전용으로 열고, 파일 디스크립터 번호를 받는다 |
| `while(Read(infd, &c, 1) != 0)` | 1바이트씩 읽는다. 파일 끝(EOF)에 도달하면 0을 돌려주므로 반복이 끝난다 |
| `Write(STDOUT_FILENO, &c, 1);` | 읽은 1바이트를 표준 출력(1번, 화면)에 쓴다 |
| `exit(0);` | 정상 종료 |

여거서 왜 argc == 2가 나오냐면<br>
argv[0]	"./showfile1_nobuf" (프로그램 자기 이름)<br>
argv[1]	"hello.c" (내가 넘긴 파일 이름)<br>
argc	2

리눅스에서 프로그램이 파일을 열면 커널은 그 파일을 가리키는 번호(파일 디스크립터)를 돌려준다.
프로그램이 시작될 때 0, 1, 2번은 이미 열려 있다.

| 번호 | 이름 | 연결된 곳 |
|---|---|---|
| 0 | STDIN_FILENO (표준 입력) | 키보드 |
| 1 | STDOUT_FILENO (표준 출력) | 화면 |
| 2 | STDERR_FILENO (표준 에러) | 화면 |

그래서 Open()으로 새로 연 파일은 보통 3번을 받는다.
파일 이름 없이 실행하면 infd가 0번 그대로 남아 키보드 입력을 읽고, Ctrl+D를 누르면 EOF로 끝난다.

대문자 함수 (래퍼 함수)

Open, Read, Write는 리눅스 시스템 콜 open, read, write를 감싼 함수이다.
시스템 콜을 호출한 뒤 에러(-1)가 나면 에러 메시지를 출력하고 프로그램을 끝낸다.
매번 if 문으로 에러를 검사하는 코드를 줄이기 위해 쓴다.

```c
ssize_t Read(int fd, void *buf, size_t count) 
{
    ssize_t rc;

    if ((rc = read(fd, buf, count)) < 0) 
	unix_error("Read error");
    return rc;
}
```

실행

```bash
make showfile1_nobuf
./showfile1_nobuf hello.c
```

hello.c의 내용이 화면에 그대로 출력된다.

시스템 콜 횟수 확인

strace를 쓰면 프로그램이 호출한 시스템 콜을 볼 수 있다.

```bash
sudo apt install -y strace
strace -e trace=read,write ./showfile1_nobuf hello.c
```

```
read(3, "#", 1)                         = 1
write(1, "#", 1)                        = 1
read(3, "i", 1)                         = 1
write(1, "i", 1)                        = 1
...
read(3, "", 1)                          = 0
```

191바이트인 hello.c를 출력할 때 호출 횟수를 세면 다음과 같다.
(프로그램 시작 시 라이브러리를 불러오는 read 1번은 제외)

| 프로그램 | 한 번에 읽는 양 | read 횟수 | write 횟수 | 합계 |
|---|---|---|---|---|
| showfile1_nobuf | 1바이트 | 192 | 191 | 383 |
| showfile2_buf | 64바이트 | 4 | 3 | 7 |

read 횟수가 파일 크기보다 1번 많은 이유는 마지막에 EOF를 확인하는 read가 한 번 더 있기 때문이다.

정리

시스템 콜은 사용자 모드에서 커널 모드로 전환해 커널에 일을 부탁하는 것이라, 일반 함수 호출보다 비용이 크다.
showfile1_nobuf는 글자마다 이 전환을 두 번씩 하므로 파일이 커질수록 매우 느려진다.
같은 결과를 내더라도 버퍼에 모아서 한 번에 읽고 쓰면 시스템 콜 횟수를 크게 줄일 수 있고,
이것이 showfile2_buf부터 showfile5_mmap까지 이어지는 실습의 핵심이다.

바꾼 부분 설명

|원래 코드	|바꾼 코드|	의미|
|---|---|---|
|char c;	|char buf[512];	|한 번에 담을 수 있는 양을 1바이트에서 512바이트로 늘림|
|Read(infd, &c, 1)	|Read(infd, buf, sizeof(buf))	|"최대 512바이트까지 읽어서 buf에 넣어 줘"|
|(없음)	|int short_count|	read()가 실제로 읽은 바이트 수를 저장|
|Write(..., &c, 1)|	Write(..., buf, short_count)	|읽은 만큼만 출력|

`read()`에 512바이트를 달라고 해도, 항상 512바이트가 오는 건 아니에요.
hello.c는 191바이트라서 첫 `read()`는 191을 돌려줘요. 이렇게 요청한 
것보다 적게 읽히는 걸 short count라고 해요.

만약 `Write(STDOUT_FILENO, buf, 512)`처럼 고정값을 쓰면, 
191바이트 뒤에 buf에 남아 있던 쓰레기 값 321바이트까지 같이 출력
돼요. 그래서` read()`의 반환값을 받아 두었다가 그만큼만 `write()`해야 해요.
